# 测试用例设计 Skill

把功能点、需求描述、PRD 片段或代码变更说明，转成结构化、可执行的测试用例集。

## 适用场景

- 拿到一个功能点（如"登录""优惠券核销"）需要快速产出用例
- 已有用例覆盖不全，需要按方法补测边界、异常、组合场景
- 需求评审前需要梳理测试点，暴露需求中的规则空白

不适用：执行自动化测试、定位缺陷根因、代码调试。

## 触发方式

在对话中直接说明需求即可，例如：

- 为登录功能设计测试用例
- 补充订单模块的测试点
- 这个需求的测试覆盖够吗

## 设计方法选型

| 需求特征 | 首选方法 |
|---|---|
| 输入域、字段校验、数值或长度限制 | 等价类划分 + 边界值分析（成对使用） |
| 多条件组合的业务规则 | 判定表 / 因果图 |
| 端到端业务流程 | 场景法（基本流 + 备选流 + 异常流） |
| 多参数、多环境配置组合 | Pairwise / 正交试验 |
| 对象有明确状态流转 | 状态迁移法，覆盖合法与非法迁移 |
| 任何场景 | 错误推测法补充 |

## 输出格式

固定 8 列：用例编号 / 用例标题 / 设计方法 / 优先级 / 前置条件 / 测试步骤 / 测试数据 / 预期结果。

优先级定义：

- P0：最高优先级，主流程必过，不通过则阻塞发布
- P1：核心分支，上线前必测
- P2：边界与异常，常规回归覆盖

## 使用限制

- 依赖输入的需求信息；关键规则缺失时会先提问澄清，或显式列为"待确认假设"
- 不编造需求中不存在的业务规则
- 只产出用例，不负责执行、不产出自动化脚本
